Operation map / 06 gates

它怎么执行

不是把几个 Agent 拉进群聊。每一步都留下可回看的决定、收据与产物，下一步只在门禁满足后发生。

  1. 01
    Observe / Publish

    先确认谁能做，再把意图变成任务

    Doctor 观察当前 Agent 能力；用户明确选择 Installation Leader 并发布任务。任务目标、风险与预期证据从这里进入可审计记录。

    USER INTENTcapability passport
    task.md + approval risk
  2. 02
    Declare

    Leader 拆解工作，并声明角色

    Leader 定义 WorkItems，指定谁实现、谁只读复核，并为每项工作声明必须返回的证据。VALP 不会暗中替用户选择 Leader，也不会替 Leader 偷换 Agent。

    ASSIGNMENTWorkItems + roles
    expected evidence refs
  3. 03
    Validate / Dispatch

    先过能力与权限检查，再公开派工

    VALP 检查能力、上下文、Skill、权限与证据契约；运行时通过 preflight 后绑定 Worker 会话并可见派发。只把文字塞进窗口，不等于真正提交。

    VISIBLE HANDOFFpreflight + binding
    dispatch_submitted
  4. 04
    Execute / Verify

    Worker 做事，也必须交出证据

    Worker 执行、研究或制作，并返回精确产物、命令记录和身份绑定的完成收据。验证针对真实文件与真实工具输出，不接受一句“done”代替结果。

    WORKER RETURNartifact + command log
    dispatch_completed
  5. 05
    Review / Correct

    独立复核；有问题就有界返工

    Reviewer 以只读方式检查同一份精确产物。严重问题进入修复、再派发、再验证、再复核；最多三轮，同一阻塞重复出现就缩小范围或停下来问用户。

    INDEPENDENT CHECKfindings + review
    correction-cycle
  6. 06
    Resolve / Audit

    处理建议与审批，最后才审计收口

    Leader 处理各 Agent 的建议；高风险动作等待用户批准；随后记录最终结论与反馈。valp audit 检查整条证据链，生命周期状态再单独进入 Done、Blocked 或 Failed。

    GATED CLOSURErecommendations + approval
    audit + final state
The key distinction

运行时显示 completed，只说明执行状态变化；只有收据、预期证据、验证、独立复核和审计一起闭合，VALP 才接受完成主张。

Authority map / no hidden control

谁控制什么

Agent 可以很聪明，但权限不能含糊。决定权、执行权、复核权和裁决权被刻意拆开。

UUser
选择 Leader；设定目标；批准发布、上传、释放、认证或破坏性操作。
Boundary未明确批准时，高风险动作停在门外。
LLeader
拆解 WorkItems；声明 Worker 与 Reviewer；综合结果；决定建议如何进入当前范围。
Boundary不能绕过用户批准，也不能把自己的判断伪装成 Worker 证据。
WWorker
在限定范围内执行任务；使用可达工具；返回精确产物、命令证据与建议。
Boundary“我完成了”不是证明；不能自行扩大权限或发布结果。
RReviewer
独立、只读地检查实现与证据；记录阻塞问题、风险和可操作建议。
Boundary不修改被审对象；复核结论不能替代缺失的原始证据。
VVALP
验证声明、控制派发门禁、记录收据、检查证据链并运行确定性审计。
Boundary协议不秘密选择 Agent，不制造证据，也不把图表当成事实。
Advisory brainOntology

帮助分解、路由与投影上下文；它给建议，不给完成证明。

ProofEvidence

真实产物、收据与验证记录；每个主张都能回到精确引用。

JudgeAudit

确定性检查门禁是否闭合；不是模型投票，也不是视觉印象。

Read-only dashboardTask Graph

把已有任务事实投影给用户看；只读，不改变证据或审计状态。

Acceptance desk / final gate

什么时候才算完成

完成不是一句话，也不是一个绿色状态灯。它是一组能被别人重新检查的事实。

  • VLeader 声明的全部预期证据都存在，并指向任务内的精确产物。
  • V真实提交与完成收据绑定到正确的 Agent、会话和 WorkItem。
  • V验证通过；独立复核没有未解决的 critical / high 阻塞项。
  • V所有选中 Agent 的建议已接受、合并、限定后续、拒绝或升级，不被静默忽略。
  • V需要用户批准的动作已经明确批准；没有从沉默中推断权限。
  • V最终综合与反馈已记录；valp audit 返回 fail_count=0。
